Assignment 1

Short, easy, and humanized answers on web development basics.

1. Frontend, Backend, and Full-Stack

Frontend

Frontend is what users see and click. Example: the Netflix screen or a shopping website page.

Backend

Backend is the hidden part that handles data and logic. Example: saving login details on a server.

Full-stack means working on both sides. Example: building a small online shop from page design to database.

2. Client-Server Model

The client asks, the server responds, and the server can also fetch data from the database.

Client (Browser)  --->  Server  --->  Database
       ^                |
       |----------------|

3. How a Browser Loads a Page

The browser sends a request to the web server, gets the files back, reads HTML first, then loads CSS, JavaScript, and images. After that, it shows the page on the screen.

4. Tools Needed for Web Development

  1. VS Code - for writing code.
  2. Browser - for testing the website.
  3. Live Server - for quick preview.
  4. Git - for version control.
  5. Node.js - for running JavaScript tools.

5. What is a Web Server?

A web server is a computer or software that sends web pages to browsers when they request them. Common examples are Apache, Nginx, and Microsoft IIS.

6. Roles in a Project

Frontend developer: makes the UI look good and work smoothly.

Backend developer: manages server logic, APIs, and data.

Database administrator: keeps the database safe, fast, and organized.

7. VS Code Setup

Install VS Code, add the Live Server extension, and use a browser for testing HTML, CSS, and JavaScript.

8. Static vs Dynamic Websites

Static website: same content for everyone. Example: a personal portfolio.

Dynamic website: content changes based on user or data. Example: Facebook or Amazon.

9. Five Web Browsers

Google Chrome, Mozilla Firefox, Microsoft Edge, Safari, and Opera.

Chrome, Edge, and Opera use Blink; Firefox uses Gecko; Safari uses WebKit.

10. Basic Web Architecture Flow

Client requests data, the server processes it, APIs connect services, and the database stores information.

User / Client -> Browser -> Server -> API -> Database
                     ^                         |
                     |-------------------------|
Simple idea: the browser asks, the server responds, and the database stores the data.
